# Holon Navigator — decomposed

This is the single-file `holon-navigator.html` artifact (~11,000 lines) split
into functional components for readability and editing. It is a mechanical
decomposition only — no logic was changed, and the two client identifiers
("causalspark" / "frameworkIsland") that were previously genericized to
"acmeco" / "exampleOrg" remain genericized throughout.

## Important: this is not a real module system

The original file is one big self-invoking function
(`(function(){ ... })();`) whose ~270 helper functions and shared variables
(`BANK`, `DATASET`, `holons`, `deprecatedSet`, and so on) all live in one
JavaScript closure. Splitting that closure across separate `<script>` tags,
or into ES modules with `import`/`export`, would be a real refactor —
renaming collisions, load-order dependencies, and closure-captured state all
have to be worked out by hand, and none of that has been done here (doing it
blind, without a way to run and click through the app afterwards, would risk
quietly breaking something).

So the split below is **organizational, not architectural**: each file in
`js/` is an exact, verbatim slice of the original script, grouped by what it
does. They only run correctly when concatenated back together, in order,
inside the original wrapping function — which is exactly what `dist/app.js`
already is. `dist/app.js` was generated by concatenating `js/01...` through
`js/15...` in numeric order inside `(function(){ ... })();`, and it has been
diffed byte-for-byte against the original script and is identical.

## Structure

```
index.html          -- page shell; loads styles.css and dist/app.js
styles.css           -- all CSS, extracted verbatim from the original <style> block
js/                   -- the script body, sliced into 15 topical files (read/edit here)
dist/app.js          -- js/01...js/15 concatenated back into one working script
build.sh              -- regenerates dist/app.js from js/*.js, in order
```

Open `index.html` in a browser and it behaves exactly like the original
single-file artifact.

## The 15 component files, in load order

| File | What it covers |
|---|---|
| `01-bridge-connection-and-core-queries.js` | Connector/bank/dataset config, the `callTool` loading-bar wrapper, containment vs. connection predicate logic, core SPARQL query builders (list, detail, references) |
| `02-taxonomy-and-holon-crud-backend.js` | SKOS concept/scheme CRUD SPARQL builders, deprecated-status tracking, holon parent/child/echo-property logic, Turtle-building helpers, create/update SPARQL for a holon |
| `03-shape-driven-property-editor.js` | Loading and rendering SHACL property shapes against a holon, the generic form controls that back "Properties" editing on the detail panel |
| `04-holon-relationships.js` | The Parent/Child/Connection relationship editor fields on the detail panel |
| `05-tab-state-and-shared-render-helpers.js` | Per-tab state (deprecated/deactivated visibility), formatting helpers (dates, markdown, escaping), and the All Holons / By Type / Containment Tree views |
| `06-taxonomies-tab-ui.js` | The Taxonomies tab: browsing/editing SKOS schemes and concepts |
| `07-shacl-shapes-shared.js` | Shared SPARQL builders and queries used by both the Node Shapes and Property Shapes tabs |
| `08-node-shapes-tab-ui.js` | The Node Shapes tab: rail, detail view, edit/create forms |
| `09-property-shapes-tab-ui.js` | The Property Shapes tab: rail, detail view, edit/create forms |
| `10-classes-tab-ui.js` | The Classes tab (raw ontology vocabulary) |
| `11-properties-tab-ui.js` | The Properties tab (raw ontology vocabulary) |
| `12-namespaces-tab-ui.js` | The Namespaces tab: prefix/URI registry, namespace rewriting/migration |
| `13-holon-detail-panel.js` | The main holon detail panel: rendering, Add Child, Add Connection, Edit forms |
| `14-holon-actions.js` | Delete, "add a type", create-of-type, and holon selection |
| `15-app-bootstrap-and-lifecycle.js` | Dataset/bank/server switching, `init()`, `refreshAll()`, and the top-level event wiring |

## Rebuilding after an edit

If you change one of the files under `js/`, regenerate `dist/app.js`:

```bash
bash build.sh
```

This just concatenates `js/01...` through `js/15...` in order inside the
wrapping `(function(){ ... })();` — the same thing that produced the
`dist/app.js` shipped here.
